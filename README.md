# Code File & Function Tree

Дърво в Activity Bar-а на VSCode с файловете от workspace-а (`.pl`, `.pm`, `.cgi`, `.html`, `.js`, `.css`, `.ts`, `.tsx`, `.sh`, `.json`, и файлове без разширение с shebang за shell), а под всеки `.pl`/`.pm`/`.cgi`/`.js`/`.ts`/`.tsx`/`.sh`/shell-файл — функциите, дефинирани в него.

## Какво прави

- **Дърво**: папки → файлове → функции, вложени едно в друго.
- **Двоен клик върху файл** — отваря файла. Единичен клик само разгъва/свива клона му в дървото.
- **Клик върху функция** — отваря файла с курсора в началото на функцията.
- **Синхронизация с курсора** — докато местиш курсора в отворен файл, функцията, в която се намираш, автоматично се маркира в дървото.
- Дървото се обновява при създаване/изтриване на файлове и при запис (за да прихване нови/премахнати функции).

## Go to Definition

В Perl/JS/TS/shell файл: `F12` или `Ctrl`+клик върху името на функция скача до дефиницията ѝ.

- Търси се в целия проект, но само във файлове на същия език (извикване от `.pl` намира `sub` в `.pl`/`.pm`/`.cgi`, не функция със същото име в `.js`).
- Разпознават се и Perl имена с пакет (`Foo::Bar::baz`).
- Ако функцията е дефинирана на няколко места, VS Code показва списък с всички.
- Ако под курсора няма позната функция, но има път към файл (напр. `lib/Utils.pm` в `require`/`use`/`import`), се отваря този файл — както при **Open Selected File** по-долу.

## Code Tree: Open Selected File (`Alt+O`)

Отваря файла, чийто път е под курсора — напр. `require "lib/Utils.pm";`, `<script src="js/app.js">`, `<TMPL_INCLUDE NAME=group_permissions.html>`, `source ./env.sh`. Командата е достъпна и от Command Palette.

- Първо пътят се търси спрямо папката на текущия файл.
- Ако там няма такъв файл, се търсят файлове със същото име навсякъде в проекта (сред показаните в дървото).
- При повече от едно съвпадение се показва списък за избор.
- Разпознава се всеки текст от вида `път/до/файл.разширение` (букви, цифри, `_`, `-`, `.`, `/`), без значение от езика на файла.

## Настройки

- `JChCodeTree.showHiddenFiles` (по подразбиране `false`) — дали да се показват файлове и папки, чието име започва с `.` (включително папки от multi-root workspace, напр. `.claude`). При промяна дървото се обновява автоматично.
- `JChCodeTree.showSymlinks` (по подразбиране `false`) — дали да се показват файлове и папки, достъпни през symlink (под името на линка). Когато е включена, папките се обхождат директно, независимо от `search.followSymlinks`; защитено е от зацикляне, а `node_modules`/`.git`/`.svn`/`.hg`/`CVS` се пропускат. Тогава е нормално Go to Definition и `Alt+O` да дават дублирани резултати.
- `JChCodeTree.updateFolder` (по подразбиране празно = изключено) — папка с `JCh-code-tree-x.y.z.vsix` файлове (напр. `version/` от `npm run package` или мрежова папка). При всяко отваряне на прозорец, ако там има по-нова версия от текущата, тя се инсталира автоматично и се предлага Reload. Задава се само в User settings (не в workspace). Ако папката е в git clone, преди проверката се прави `git pull --ff-only` (грешките се игнорират).

## Обновяване през git

`npm run package` оставя само последния `.vsix` във `version/` (по-старите отиват във `version/old/`, който не се commit-ва). Новата версия се публикува с commit + push на `version/`.

За да се обновява автоматично на дадена машина — еднократно:

```sh
git clone git@github.com:<user>/<repo>.git ~/.jch-code-tree
```

и в User `settings.json`: `"JChCodeTree.updateFolder": "~/.jch-code-tree/version"`. Clone-ът трябва да е отделен от работното копие, в което се разработва.

## Разпознаване на функции

Ползва се regex, не истински parser:

- Perl: `sub name { ... }`
- JS/TS: `function name()`, `const name = function/() => {}`, методи в клас/обект (`name(...) {}`), включително типови анотации (`: Type`, `<T>`) и `public`/`private`/`protected`/`readonly` модификатори
- Shell (`.sh` и файлове без разширение с `#!.../bash` или подобен shebang): `function name { ... }`, `name() { ... }`

Покрива обичайните случаи, но може да пропусне екзотични конструкции (напр. сигнатура на няколко реда).

## Известни ограничения

- Списъкът с разширения, които се показват, засега е фиксиран в кода — настройка за това предстои.
- `.html`/`.css`/`.json` файловете се показват в дървото, но без вложени функции.
- По подразбиране файлове и папки, достъпни през symlink, не се показват — само реалните пътища (за да няма дублирани резултати). Ако отвориш файл през symlink (напр. от Explorer-а), той се свързва с реалния си файл в дървото и синхронизацията с курсора работи. Не работи, ако реалният файл е извън workspace-а или ако самата workspace папка е symlink.
- Файл без разширение се показва само ако първият му ред е shebang, сочещ към shell (`sh`/`bash`/`zsh`/`ksh`/`dash`).
